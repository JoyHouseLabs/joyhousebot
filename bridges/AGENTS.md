# Channel Bridge 协作说明

`bridges/` 用于必须独立进程运行的渠道桥接器。Bridge 只负责渠道协议、消息规范化、签名校验、投递回执
和连接生命周期。

- 所有入站消息通过公共执行入口创建 Run，不能直接调用 Agent 内部对象。
- 所有出站结果使用统一 Channel 投递与 Outbox 语义，不能把“请求已接收”当作“已送达”。
- Bridge 不保存 Runtime 最终状态，不创建独立会话/任务事实源。
- 渠道凭据仅使用环境变量或 `env://` 引用，日志必须脱敏。
- 通用、可随 Worker 加载的渠道优先做成 `extensions/channel-*`；只有进程或协议隔离确有必要时才放这里。
